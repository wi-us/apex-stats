Team Plate Detection & Identification Module
1. Назначение модуля

Модуль предназначен для автоматического поиска плашек команд на видеозаписи матча Apex Legends / ALGS, идентификации команд и формирования данных для построения траекторий команд на карте.

В общем проекте этот модуль отвечает только за одну часть конвейера обработки:

видеозапись матча
↓
кадры видео
↓
поиск плашек команд
↓
идентификация команды по плашке
↓
агрегация плашек в точку команды
↓
tracks.json для web-интерфейса

Модуль не занимается полным анализом матча. Он должен быть интегрирован с остальными частями проекта:

определение кольца;
определение вылетов команд;
компенсация смещения камеры наблюдателя;
отображение результата в web-интерфейсе;
работа с базой данных матчей, команд и стартовых зон.

Главный результат работы модуля — файл game_5_tracks.json или аналогичный файл с точками команд по времени.

2. Основная задача

На карте трансляции отображаются цветные плашки команд. Каждая команда может иметь до трёх игроков, поэтому на карте может быть несколько плашек одной команды.

Модуль должен:

найти плашки команд на кадре;
определить, какой команде принадлежит каждая плашка;
объединить несколько плашек одной команды в одну точку;
стабилизировать движение точки по времени;
сохранить результат для web-интерфейса.

Особая сложность заключается в том, что команды могут иметь похожие цвета. Например, BB и THUG долго путались между собой. Поэтому идентификация не должна строиться только на цвете. В модуле используется несколько признаков:

цвет плашки;
список команд текущего матча;
размер плашки;
стартовая зона команды;
предыдущее положение команды;
запрет на резкие скачки;
перенос предыдущей точки при временной потере команды.
3. Текущая логика работы
Общий конвейер
flowchart TD
    A[Видео матча] --> B[Извлечение кадров]
    B --> C[Поиск плашек команд YOLO]
    C --> D[Извлечение признаков плашки]
    D --> E[Цветовые кандидаты]
    D --> F[Профиль размера плашки]
    E --> G[Идентификация команды]
    F --> G
    H[SQLite: команды и стартовые зоны] --> G
    I[Предыдущие позиции команд] --> G
    G --> J[Агрегация плашек команды]
    J --> K[Стабилизация трека]
    K --> L[tracks.json]
    L --> M[Web-интерфейс / карта матча]
Основная идея

YOLO-модель отвечает только за поиск объекта team_plate. Она не определяет конкретную команду. После поиска плашки отдельный слой логики определяет команду по нескольким признакам.

4. Основные скрипты модуля
4.1. identify_match_plates.py

Главный скрипт для поиска плашек команд и первичной идентификации.

Назначение
открывает видео или набор изображений;
берёт кадры с заданным шагом;
вырезает центральную область карты;
запускает YOLO-модель;
находит плашки команд;
считает цвет плашки;
формирует список цветовых кандидатов;
сохраняет detections.csv, detections.jsonl, summary.json;
может сохранять debug-изображения.
Входы
видео матча;
веса YOLO-модели;
конфигурация матча;
HSV-пресеты цветов команд;
параметры обработки.
Выходы
detections.csv;
detections.jsonl;
summary.json;
папка debug/ с проверочными изображениями.
Ключевые параметры
--video             путь к видео
--weights           путь к YOLO-модели
--config            путь к config JSON
--hsv-presets       путь к HSV-пресетам
--prefer-presets    использовать HSV-пресеты как основной источник цвета
--out               выходная папка
--sample-fps        частота обработки кадров
--imgsz             размер изображения для YOLO
--conf              минимальная уверенность YOLO
--device            cpu или cuda
--min-color-score   минимальная оценка совпадения по цвету
--keep-unknown      сохранять спорные/неизвестные плашки
--save-debug        сохранять debug-кадры
4.2. build_color_profiles_from_hsv_presets.py

Создаёт цветовые профили команд из HSV-пресетов и конфигурации матча.

Назначение

Скрипт нужен, чтобы связать слоты команд, теги команд и HSV-диапазоны. Важно: в build_tracks_from_detections.py нужно передавать именно готовый файл профилей цветов, а не сырой файл HSV-пресетов.

Входы
config JSON матча;
HSV-пресеты карты;
выходной путь.
Выходы
*.preset_colors.json.
Важное замечание

Нельзя передавать сырой hsv_presets.storm-point.json как --color-profiles при сборке треков. Это приводит к появлению лишних слотов вида SLOT_1, SLOT_2, а реальные команды могут оказаться в дополнительных слотах.

Правильно:

--color-profiles configs/01KH2HK109T8T08WHXMJ1B4412.preset_colors.json

Неправильно:

--color-profiles configs/hsv_presets.storm-point.json
4.3. export_poi_priors.py

Создаёт файл стартовых зон команд из SQLite.

Назначение

Стартовые зоны помогают отличать команды с похожими цветами в начале матча. Если две команды имеют похожий цвет, система может проверить, какая из них должна находиться ближе к своей стартовой зоне.

Входы
база SQLite;
series_id;
номер матча;
config JSON;
размер карты;
параметры области карты.
Выходы
*.match5_poi_priors.json.
Логика

Скрипт берёт из базы данных:

список команд матча;
карту матча;
стартовые зоны;
координаты стартовых зон.

Далее он формирует JSON, который используется при сборке tracks.json.

4.4. build_plate_size_profiles.py

Создаёт профили размеров плашек команд.

Назначение

У разных команд плашки имеют разную ширину из-за длины названия или тега. Этот признак помогает различать команды с похожими цветами.

Например, если цвет плашки похож на BB и THUG, размер плашки может помочь выбрать более вероятную команду.

Входы
detections.csv;
минимальная уверенность детекции;
минимальная оценка цвета;
минимальное количество примеров.
Выходы
*.plate_sizes.json;
опционально *.plate_sizes.csv.
Что сохраняется

Для каждой команды:

медианная ширина;
медианная высота;
медианное соотношение ширины и высоты;
диапазоны размеров;
количество использованных примеров.
4.5. build_tracks_from_detections.py

Собирает итоговый tracks.json из найденных плашек.

Назначение

Скрипт берёт detections.csv, цветовые профили, стартовые зоны, профили размеров и формирует точки команд по времени.

Главные функции
выбирает кандидатов команды для каждой плашки;
использует цвет, размер, стартовую зону и прошлую позицию;
объединяет несколько плашек одной команды в одну точку;
рассчитывает точку немного ниже центра плашки;
запрещает резкие скачки;
переносит прошлую позицию при кратковременной потере команды;
сохраняет tracks.json.
Входы
detections.csv;
config JSON;
цветовые профили;
стартовые зоны;
профили размеров;
параметры стабилизации.
Выход
game_5_tracks.json.
Ключевые параметры
--anchor-y-ratio       где внутри bbox ставить точку команды
--use-candidates       использовать список кандидатов по цвету
--candidate-margin     насколько близкие кандидаты допускаются
--size-profiles        профиль размеров плашек
--size-weight          вес размера при выборе команды
--poi-priors           стартовые зоны команд
--drop-gate            допустимое расстояние до стартовой зоны
--drop-prior-seconds   сколько секунд учитывать стартовую зону
--spatial-gate         допустимое расстояние до прошлой точки
--max-jump             максимальный допустимый скачок
--reject-jumps         отклонять резкие скачки
--cluster-radius       радиус выбора плотного кластера
--max-cluster-items    сколько плашек брать в кластер
--carry                сколько шагов можно переносить прошлую точку
--carry-decay          снижение уверенности при переносе
Важная логика anchor point

Точка команды не должна ставиться строго в центр найденной рамки. Центр рамки не всегда совпадает с фактическим положением команды. Поэтому точка ставится ниже центра:

x = center_x
y = y1 + height * anchor_y_ratio

Рекомендуемое значение:

--anchor-y-ratio 0.72
4.6. render_tracks_map.py

Визуально отображает tracks.json на карте.

Назначение

Скрипт нужен для проверки результата без web-интерфейса. Он рисует точки команд на карте, соединяет последние две точки и может сохранять видео-превью.

Входы
tracks.json;
изображение карты;
номер кадра или все кадры.
Выходы
PNG-изображение выбранного кадра;
папка кадров;
MP4-превью;
suspicious_jumps.csv.
Особенности
карта масштабируется до заданного размера;
последние две точки команды соединяются линией;
подписи команд разносятся, чтобы не перекрываться;
подозрительные скачки можно сохранить в CSV.
4.7. validate_tracks_vs_detections.py

Проверяет соответствие tracks.json и detections.csv.

Назначение

Скрипт нужен, чтобы понять, где появилась ошибка:

в поиске плашек;
в идентификации команды;
в сборке tracks.json;
в отображении на сайте.
Входы
tracks.json;
detections.csv.
Выходы
CSV-отчёт о расхождениях.
Основные статусы
ok
track_without_raw_detections
raw_detections_without_track
track_far_from_raw_detections
5. Переменные запуска

Для удобства запуска в PowerShell используются переменные:

$RUN = "outputs\game5_size_profile_test"
$VIDEO = "clips\05_Game_5_02-04-42.mp4"
$WEIGHTS = "runs\detect\team_plate_v2_hardneg_cpu\weights\best.pt"
$CONFIG = "configs\01KH2HK109T8T08WHXMJ1B4412.json"
$HSV = "configs\hsv_presets.storm-point.json"
$COLORS = "configs\01KH2HK109T8T08WHXMJ1B4412.preset_colors.json"
$POI = "configs\01KH2HK109T8T08WHXMJ1B4412.match5_poi_priors.json"
$SIZES = "configs\01KH2HK109T8T08WHXMJ1B4412.plate_sizes.json"
6. Рекомендуемый порядок запуска
Шаг 1. Создать цветовые профили
python scripts\build_color_profiles_from_hsv_presets.py --config $CONFIG --hsv-presets $HSV --out $COLORS --update-config
Шаг 2. Создать стартовые зоны команд
python scripts\export_poi_priors.py --db data\algs.sqlite --series-id 01KH2HK109T8T08WHXMJ1B4412 --match-number 5 --config $CONFIG --out $POI --left-ignore 420 --roi-size 1080 --canonical-size 2000
Шаг 3. Создать новую папку прогона
Remove-Item $RUN -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force $RUN
Шаг 4. Найти плашки и создать detections
python scripts\identify_match_plates.py analyze-video --video $VIDEO --weights $WEIGHTS --config $CONFIG --hsv-presets $HSV --prefer-presets --out $RUN --sample-fps 0.1 --imgsz 640 --conf 0.20 --device cpu --min-color-score 0.25 --template-check --template-check-mode conflicts_only --conflicts BB:THUG --min-text-confirm-score 0.55 --text-check-margin 0.18 --unknown-on-unconfirmed-conflict --keep-unknown --save-debug
Шаг 5. Построить профили размеров плашек
python scripts\build_plate_size_profiles.py --detections "$RUN\detections.csv" --out $SIZES --summary-csv "configs\01KH2HK109T8T08WHXMJ1B4412.plate_sizes.csv" --min-conf 0.45 --min-color-score 0.70 --safe-margin 0.08 --min-samples 10 --skip-unknown-sources
Шаг 6. Собрать tracks.json
python scripts\build_tracks_from_detections.py --detections "$RUN\detections.csv" --out "$RUN\game_5_tracks.json" --config $CONFIG --color-profiles $COLORS --poi-priors $POI --size-profiles $SIZES --video-name "game_5.mp4" --aggregation median --anchor-y-ratio 0.72 --use-candidates --candidate-margin 0.14 --min-candidate-score 0.25 --size-weight 0.22 --min-size-score 0.18 --reject-bad-size-candidates --min-conf 0.20 --min-color-score 0.25 --min-detections 1 --spatial-gate 180 --drop-gate 260 --drop-prior-seconds 90 --max-jump 240 --reject-jumps --cluster-radius 140 --max-cluster-items 3 --carry 2 --carry-decay 0.72
Шаг 7. Проверить структуру слотов
(Get-Content "$RUN\game_5_tracks.json" -Raw | ConvertFrom-Json).meta.slots | Select-Object slot_id,broadcast_tag,color | Format-Table

Ожидаемый результат:

slot_1   ELTE
slot_2   FREE
slot_3   FXI
...
slot_10  THUG
slot_11  BB
slot_13  DINO
...

Если появляются SLOT_1, SLOT_2 и реальные команды уходят в slot_21, slot_39, значит в build_tracks_from_detections.py был передан неправильный файл --color-profiles.

8. Координаты
8.1. ROI и полный кадр

В текущем пайплайне анализируется центральная область карты размером 1080×1080. При этом слева и справа отбрасываются области по 420 px.

Важно различать координаты:

bbox_roi       координаты внутри области 1080×1080
bbox_original  координаты внутри полного кадра
frame_px       координаты точки в полном кадре

Если нужно отрисовать точку поверх 1080×1080 debug-изображения, нужно вычитать смещение слева:

x_roi = frame_px.x - 420
y_roi = frame_px.y
8.2. Каноническая карта

Для web-интерфейса желательно использовать координаты общей карты. Если модуль компенсации камеры наблюдателя уже рассчитает преобразование координат, frame_px должен переводиться в canonical_px.

В текущем модуле возможно хранение frame_px; для финальной интеграции нужно согласовать, кто отвечает за перевод координат в систему общей карты:

модуль камеры наблюдателя;
модуль построения треков;
web-интерфейс.

Если вместо этого появляются SLOT_1, SLOT_2, значит был передан неправильный файл цветовых профилей.

11. Текущие сильные стороны модуля
YOLO отвечает только за поиск плашек, а не за идентификацию команды.
Идентификация использует несколько признаков.
Есть цветовые кандидаты, а не только один выбранный цвет.
Есть стартовые зоны из SQLite.
Есть профили размеров плашек.
Есть запрет дальних скачков.
Есть перенос предыдущей позиции при временной потере команды.
Есть debug-изображения.
Есть валидация detections.csv против tracks.json.
Есть отдельный Python-рендер карты для быстрой проверки результата.
12. Возможные направления улучшения
12.1. Единая система координат

Нужно чётко определить, где и когда frame_px переводится в canonical_px.

12.2. Единый формат результатов

Желательно, чтобы данные команды, кольца, вылетов и камеры сохранялись в единой структуре или синхронизировались по времени.

12.3. Улучшение идентификации похожих команд

Для похожих цветов можно добавить визуальный классификатор плашек как дополнительный признак. Он должен использоваться только на спорных случаях, а не заменять текущую систему.

14. Краткое резюме для Codex

Этот модуль решает задачу поиска и идентификации плашек команд на карте трансляции Apex Legends. Он использует YOLO для поиска плашек, HSV-профили для цветовой идентификации, профили размеров плашек, стартовые зоны из SQLite и историю движения команды для стабилизации результата.

Модуль должен быть интегрирован в общий проект как часть конвейера анализа видео. Его основной выход — tracks.json, который содержит координаты команд по времени и используется web-интерфейсом для отображения перемещений команд на карте.
