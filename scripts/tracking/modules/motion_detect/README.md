# motion_detect — стартовые позиции команд

Модуль определяет, где на миникарте находится каждая из 20 команд в начале
матча. Это основной источник «стартовых координат» для последующего
трекинга: на статичной обсервер-камере полной миникарты команды видны
как цветные плашки, но HSV-маска одна на всё не справляется — много
статичных декораций и тёмные команды теряются.

Решение — прогнать **три независимых детектора** на одном окне кадров
и сопоставить их выводы. Если все три согласились по координате —
уверенность HIGH; две — MED; один — LOW.

Скрипт детект смертей и онлайн-трекинг находятся в отдельных модулях
и сюда не входят.

| Файл | Назначение |

## Зависимости

- `cuts.json` из `modules/find_cuts/reports/` — чтобы не семплить кадры около камера-катов

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File scripts/tracking/modules/motion_detect/push.ps1 `
  -Video scripts\tracking\game.mp4
```

Скрипт очищает `modules/motion_detect/reports/` (кроме `.gitkeep`), запускает детектор,
коммитит и пушит результаты — агент в Lovable получает их сразу.

### Параметры `motion.ps1`

| Флаг | Дефолт | Что делает |
|---|---|---|
| `-Video` | — | путь к mp4 (обязательно) |
| `-Cuts` | `modules/find_cuts/reports/cuts.json` | результат `cuts.ps1` |
| `-HsvPresets` | `configs/hsv_presets.worlds-edge.json` | HSV-пресеты карты |
| `-Zones` | `configs/zones.vod.json` | разметка зон |
| `-ZoneTag` | `minimap` | какой тег зон использовать |
| `-StartSec` | `60` | с какой секунды начать окно |
| `-Window` | `300` | сколько кадров в окне |
| `-Step` | `10` | шаг между кадрами (300×10 ≈ 50 сек @60fps) |
| `-StaticThresh` | `3` | M1: меньше — статика, выбрасываем |
| `-LinkDist` | `80` | макс. сдвиг blob'а между выборками (px зоны) |
| `-DiffThresh` | `12` | M2: порог `absdiff` бинаризации |
| `-ColorTol` | `12` | M2: макс. расстояние по H для привязки blob'а к команде |
| `-LooseH` | `5` | M3: расширение H-диапазона ±N |
| `-LooseSvDrop` | `30` | M3: понижение `S/V min` |
| `-AgreeRadius` | `0` (= `1.5 * link_dist`) | гейт согласия методов |
| `-NoPush` | — | только локальный коммит |

## Три метода

### M1 `hsv_strict`

Текущий «жёсткий» HSV-проход. `build_mask` по пресету + `find_blobs`
(`min-area=15`, `solidity≥0.55`), линковка blob'ов в траектории,
отсев тех, у кого `displacement < static-thresh`.

Хорошо ловит крупные/яркие плашки, проваливается на тёмных
(Team 5 #7a4278, Team 9 #cf512b, Team 11 #974312, Team 14 #8b6e0f
и т.п.) — у них S/V низкие, маска пустая.

### M2 `motion_diff`

Frame-difference внутри ROI minimap. `cv2.absdiff(prev_gray, cur_gray)`,
бинаризация по `--diff-thresh`, морфология, контуры. Затем для каждого
blob'а берётся медианный H пикселей под контуром и подбирается команда
с минимальной hue-дистанцией (с учётом wrap-around и порога
`--color-tol`).

Ловит ровно то, что физически двигается, поэтому статичные декорации
карты не лезут. Шум — облака, вода, минимап-эффекты.

### M3 `hsv_loose`

Тот же HSV, но H расширен на `±--loose-h`, `S/V min` понижены на
`--loose-sv-drop`, `min-area=5`, `solidity≥0.40`, `static-thresh` локально
уменьшен до `--loose-static-thresh` (по умолчанию 1 px).

Берёт тёмные/мутные плашки, которые M1 не видит. Платит шумом.

## Таблица уверенности

Для каждой команды берётся «лучшая» траектория каждого метода
(по `path_px`), считается её медианный центроид. Методы попарно
проверяются на расстояние ≤ `--agree-radius`. Размер максимальной
связной группы согласившихся методов = `agreed`.

| `agreed/present` | conf | смысл |
|---|---|---|
| `3/3` | **HIGH** | все методы видят команду в одной точке |
| `2/2` или `2/3` | **MED** | два метода согласились |
| `1/1`–`1/3` | **LOW** | методы нашли траектории, но в разных точках; вероятно реальная команда + шум |
| `0/0` | **MISS** | ни один метод не нашёл траектории |

`consensus_xy` — среднее центроидов согласившихся методов
(для HIGH/MED) или одиночная координата (для LOW).

## Чтение overlay

- **Сплошная линия** — M1 hsv_strict
- **Пунктир** — M2 motion_diff
- **Точки** — M3 hsv_loose
- **Крест с подписью `slot:CONF`** — итоговый `consensus_xy`

Если для команды видно три линии разного стиля, идущие рядом и
крест посередине → HIGH. Если кресты в стороне от линий → LOW
(методы разошлись, скорее всего ложное цветовое совпадение).

## Известные кейсы

- **`M2`/`M3` >>> `M1`** для тёмных команд — это норма; HSV-пресет
  слишком узкий, но цвет уникальный, поэтому fallback'и работают.
- **`M2` сильно шумит на воде/облаках** — поднять `--diff-thresh`
  до 18-20 или сузить minimap-зону в `/admin/zones`.
- **`agree=N/N LOW`** — все методы нашли что-то, но координаты
  разошлись > `agree_radius`. Возможно две команды одного оттенка
  на карте. Проверить overlay.
- **`MISS`** — пересмотреть HSV в `/admin/hsv` или взять более
  длинное окно (`-Window 600`).

## Что дальше

`consensus_xy` каждой команды с conf ≥ MED — это якорь, от которого
стартует онлайн-трекер. LOW-якоря используются как подсказка,
HIGH-якоря — как ground truth. Команды с MISS требуют ручной
правки HSV.

## `start_anchors.json` — для жёсткого захвата в track_teams

Помимо `motion_tracks.json` модуль экспортирует компактный файл со
стартовыми координатами и базовым радиусом `r0` по уверенности:

```json
{
  "r0_by_conf": { "HIGH": 25, "MED": 40, "LOW": 70 },
  "anchors": {
    "slot_3":  { "slot": 3,  "x": 812.3, "y": 1402.1, "conf": "HIGH", "r0_minimap_px": 25 },
    "slot_11": { "slot": 11, "x": 612.7, "y": 1750.0, "conf": "LOW",  "r0_minimap_px": 70 }
  }
}
```

`track_teams` подхватывает этот файл (если лежит рядом с
`motion_tracks.json`) и использует `r0` как стартовый радиус
гейта ассоциации. Подробности — в README `track_teams` и
конфиге `configs/da.start_anchored.yaml`.
